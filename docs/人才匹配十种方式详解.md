# 人才匹配十种方式详解

> 本文讲解系统中「选择人才」的 10 种方式，各是**拿什么数据、与什么数据、怎么匹配**。所有举例均来自当前 `.dev-data` 数据库中的真实候选人、真实岗位和真实匹配记录，不涉及代码实现。

**当前数据规模**：99 位候选人（AVAILABLE 状态）、31 个开放岗位（OPEN），已有若干真实匹配记录。

---

## 一、先建立两个核心概念

系统里有两类对象：**候选人（简历）** 和 **岗位（JD）**。匹配的本质永远是「从一类对象里，找出与另一类对象相关的人/岗位」。

为了让机器能算"相关性"，系统在导入简历和 JD 时，都会把原始内容**预处理成两份不同的文本**：

| 文本 | 用途 | 特点 |
|------|------|------|
| **关键词文本** | 给"关键词/字面匹配"用 | 尽量全，把能明确写出来的字都放进去 |
| **向量文本** | 给"语义匹配"用 | 精简，只留能代表"这个人/这个岗位是谁"的核心信息 |

> 为什么拆成两份？因为**字面匹配要"全"**（多写字才能命中），**语义匹配要"精"**（少写噪声才能聚焦含义）。混在一起反而两种都做不好。

### 这些字段如何被拆成"两份文本"

以 **徐猛** 为例，按规则会拼成下面两份（示意，均取自其真实字段）：

**① 关键词文本（字面全量）**

```
徐猛  <摘要：多年Java后端…保险科技…Agent开发…>  上海海洋大学 本科 上海 本科
太保科技有限公司 中国太平洋保险… 大模型应用工程师 高级Java工程师
LangChain LangGraph RAG Agent Python Java Spring Boot Redis Milvus Docker …
34岁 11.5年
```

> 包含：姓名、摘要/AI画像、学校/学历、地点、**全部**公司/职位、技能、年龄、年限。
> **不放**：手机号、工作职责正文、项目正文（隐私 + 噪声）。

**② 向量文本（语义精简）**

```
<摘要：多年Java后端…Agent开发…>  上海海洋大学 本科 上海 11.5年
太保科技有限公司 大模型应用工程师 LangChain LangGraph RAG Agent Python Java …
```

> 去掉姓名、历史公司/职位、年龄，只留"AI画像 + 教育 + 地点 + 年限 + 最近公司/职位 + 技能"——最能概括"这个人是做什么的"。

### 岗位侧（JD）

岗位同样被 AI 解析成结构化数据。例如真实岗位 **汇丰·资深 Java 开发工程师**：

再如真实岗位 **蚂蚁·AI Agent 架构师**：

- 最低年限：5 年；行业：金融/证券；AI 相关度：CORE_AI
- 必备技能：`AI开发框架（langchain/spring ai等）、系统架构设计（高并发高可用可扩展）、Agent核心机制（规划/工具调用/记忆）、工程优化能力`

- 最低学历：本科；地点：广州；AI 相关度：NON_AI

# 四、逐条详解（含真实举例）

## 第一类：人才库搜索（在候选人里找人）

入口是「人才库」页面搜索框，用户输入词/句，在候选人索引里搜候选人，区别只在算法。

### 方式 1：关键词检索

**拿什么数据 vs 什么数据**

- 用户输入的词（如 `LangChain`、`太保`、`微服务`） vs 候选人的**关键词文本**。

**逻辑**

1. 先把输入里的"硬条件"（年限/学历/地点等）用规则剥掉，剩下的词作为关键词；
2. 关键词和候选人的关键词文本都按"字符 n-gram"（2~3 字符片段）切碎比对；
3. 谁的关键词文本里含这些片段谁命中，按 BM25 算相关度排序；
4. 不调用 AI、不做语义理解，纯字面命中。

**真实举例**

- 搜 `LangChain` → 命中 **徐猛**（技能里明确写了 LangChain）、**张文军**（做 AI 工程化）等；
- 搜 `太保` → 命中 **徐猛**（当前公司在太保科技、前司中国太平洋保险）；
- 搜 `Flink` → 命中 **江超**（技能里写了 Flink）。

**为什么用这些数据**：关键词要能命中"任何被明确写过的字"，所以用最全的关键词文本；剥离硬条件是为了让"5年 Java"里的"5年"不干扰字面匹配。

---

### 方式 2：向量检索

**拿什么数据 vs 什么数据**

- 用户输入的一句话 vs 候选人的**向量文本**。

**逻辑**

1. 候选人的向量文本**预先**被 AI 模型转成一组数字（向量）存进索引；
2. 用户输入也转成同样的向量；
3. 计算两者向量距离，越近越相似，按相似度排序；
4. 完全不比对字面，只比对含义。

**真实举例**

- 搜 `想找一个能把大模型落地到保险业务的工程师` → 语义上命中 **徐猛**（保险 + 大模型落地）、**张文军**（保险 + AI 工程化），即使搜索词里没写"徐猛""LangChain"这些字；
- 搜 `做过金融支付的后端` → 语义命中 **江超**（京东金融支付背景）。

**为什么用这些数据**：向量要"听懂意思"，所以只保留最能概括身份的信息，去掉姓名、历史公司、年龄等噪声。

---

### 方式 3：混合检索

**拿什么数据 vs 什么数据**

- 用户输入 同时 匹配 候选人的**关键词文本**和**向量文本**。

**逻辑**

1. 关键词检索和向量检索**同时并行**跑，各出一份排序；
2. 用 RRF（倒数排名融合）合并成一份综合排名；
3. 再用语义重排模型精排一遍。

**真实举例**

搜 `Java 后端 大模型` → 关键词通道命中字面含 `Java`/`后端` 的人（徐猛、江超、张文军等），向量通道命中"大模型"语义相近的人（徐猛、张文军），融合取优。

**为什么用这些数据**：关键词"认字面、准但漏同义"，向量"懂意思、广但可能飘"，混合取长补短。

---

### 方式 4：精确筛选

**拿什么数据 vs 什么数据**

- 用户填的**结构化条件** vs 候选人的**结构化字段**（不是文本，是明确数值/枚举）。

**逻辑**

按字段做"是/否"硬过滤，不参与排序打分：

| 字段组 | 匹配的候选人数据 | 匹配方式 |
|--------|----------------|---------|
| 年限 / 年龄 | 工作年限、年龄 | 数值范围 `>=`/`<=` |
| 学历 | 最高学历 | 层级包含（"本科"=本科+硕士+博士） |
| 现居 / 意向城市 | 地点 | 精确命中 |
| 学校等级 / QS | 学校标签、QS 排名 | 层级包含 / 上限 |
| 姓名 / 公司 / 职位 / 学校 | 对应字段 | 字段内子串匹配 |
| 手机号 / 性别 | 手机号指纹、性别 | 数据库精确比对 |
| 排除技能 | 技能 | 命中即剔除 |

**真实举例**

- 筛 `上海 + 本科及以上 + 5年以上` → 命中 **徐猛**（上海 / 本科 / 11.5 年）等；
- 筛 `985` → 命中学校为 985 的候选人（如 **江超**，武汉大学 985）；
- 筛 `排除Python` → 把技能含 Python 的人剔除。

**为什么用这些数据**：这些是"确定性条件"，不该靠相似度猜；手机号/性别在文本里表达不了，下沉到数据库精确比对。

## 第二类：人选匹配岗位（给一个人选推荐岗位）

入口是候选人列表里的「匹配」按钮。方向是：**把候选人的文本当"查询"，去岗位索引里搜岗位**。

### 方式 5：人选匹配岗位·关键词模式

**拿什么数据 vs 什么数据**

- 候选人的**关键词文本** vs 岗位的**关键词文本**（= 公司+职位+JD原文+结构化结果）。

**逻辑**

把候选人关键词文本拿去岗位索引做字面（FTS）匹配，找出 JD 文本里字面相关的岗位；再对命中的岗位做硬条件过滤（年限/学历/地点/排除技能）和打分。

**真实举例（来自真实匹配记录）**

候选人 **仲启超**（Python 背景）关键词匹配「智能体架构师」岗位：

- 命中技能：`Python`
- 缺失技能：`LangGraph、CrewAI、AutoGen、向量数据库、高阶RAG、asyncio异步编程…`（该岗位要求大量 Agent 框架能力，他不具备）
- 综合分：0.2788

> 这就是"字面命中"的典型效果：他简历里明确写了 Python，所以字面命中；但岗位要求的一堆 Agent 框架他一个没写，于是大量缺失。

---

### 方式 6：人选匹配岗位·向量模式

**拿什么数据 vs 什么数据**

- 候选人的**向量文本** vs 岗位的**向量文本**。

**逻辑**

把候选人向量文本转成向量，去岗位索引按向量相似度找语义相近的岗位，再硬条件过滤和打分。

**真实举例**

**张文军** 的向量文本是"保险 + AI 工程化 + 大模型微调 + RAG"，语义上会命中「汇丰·AI研发效能全栈工程师」（保险 + LLM 落地）这类岗位，即使该 JD 里没写"众安""张文军"。

---

### 方式 7：人选匹配岗位·混合模式

**拿什么数据 vs 什么数据**

- 候选人**关键词文本 + 向量文本** 同时 匹配 岗位**关键词文本 + 向量文本**。

**逻辑**

关键词文本走字面、向量文本走语义，两者并行 + RRF 融合 + 语义重排，再硬条件过滤和打分。

**真实举例（来自真实匹配记录）**

候选人 **冯冀川**（21 年经验）混合匹配「技术业务分析师（WMT）」岗位：

- 命中技能：`API`
- 综合分：0.4

> 补充：这一类的三种模式，最终都会对召回的岗位再做一次**硬条件校验**（岗位要求的最低年限、学历、地点、排除技能），不满足的岗位被剔除，剩余按综合分排序。

## 第三类：岗位匹配人选（给一个岗位推荐人选）

入口是岗位列表里的「匹配候选人」按钮。方向是：**把岗位的"画像要求"当"查询"，去候选人索引里搜候选人**。

### 方式 8：岗位匹配人选·关键词模式

**拿什么数据 vs 什么数据**

- 岗位的**查询文本**（= 候选人画像要求 + 必备技能 + 必须条件） vs 候选人的**关键词文本**。

**逻辑**

把岗位画像和必备技能拼成一段查询文字，去候选人索引做字面匹配；召回后再对候选人做**技能覆盖打分 + 年限打分**，综合排序。

**真实举例（来自真实匹配记录）**

「GFMT 全栈开发工程师」岗位（要求 Java/Spring Boot/微服务/CI-CD/DevOps/Jenkins/OpenShift 等）关键词匹配到：

- **VIKKI**（10 年）：命中 `Java、Spring Boot、CI/CD、DevOps、Jenkins`，缺失前端框架 `Lit Elements/Angular/React` 等 → 综合分 0.2632
- **徐猛**（11.5 年）：命中 `Java、Spring Boot、Jenkins`，缺失 `微服务架构、CI/CD、DevOps` 等 → 综合分 0.1579

> 两人都命中 Java/Spring Boot，但 VIKKI 多命中了 CI/CD、DevOps，所以排得更靠前——这就是"技能覆盖分"在起作用。

---

### 方式 9：岗位匹配人选·向量模式

**拿什么数据 vs 什么数据**

- 岗位的**查询文本**（画像+技能） vs 候选人的**向量文本**。

**逻辑**

把岗位画像要求转成向量，去候选人索引按语义相似度找人，再技能覆盖 + 年限打分。

**真实举例**

「蚂蚁·AI Agent 架构师」岗位画像"需要能设计高并发高可用系统、主导过 0 到 1 的 Agent 项目、有金融业务经验"，语义上会命中那些 AI 画像里写了"Agent""高并发""金融"的候选人，即使他们简历里没写"Spring AI"字样。

---

### 方式 10：岗位匹配人选·混合模式

**拿什么数据 vs 什么数据**

- 岗位**查询文本** 同时 匹配 候选人的**关键词文本 + 向量文本**。

**逻辑**

岗位画像和技能，字面上匹配候选人关键词文本、语义上匹配候选人向量文本，两者并行 + RRF 融合 + 语义重排，再技能覆盖 + 年限打分。

**真实举例**

「汇丰·资深 Java 开发工程师」要求"Java + Spring 生态 + AI 辅助开发 + 保险"，字面命中写了 `Java`/`Spring Boot` 的人（如徐猛、江超），语义命中"保险 + 大模型"背景的人（如徐猛、张文军），融合后按综合分排出最合适人选。

> 补充：这一类的三种模式，最终对每个候选人的排序分由三部分组成——
> **相关性分（50%）+ 技能覆盖分（35%）+ 年限分（15%）**。
> 其中"技能覆盖"是逐字核对岗位必备技能是否在候选人简历中出现（用词边界精确匹配，避免 `Java` 误当成 `JavaScript`）。

> 观察：同样关键词模式，「GFMT 全栈」能精确命中 Java/Spring Boot/CI-CD 等，是因为这些词在候选人关键词文本里是**明确写出的技能词**；而「智能体架构师」要求 LangGraph/CrewAI/AutoGen，候选人简历里没写，就命中不了——这正是关键词模式"认字面"的体现。

# 六、一图看懂数据流向

```
候选人简历 ──解析──▶ 关键词文本（字面全量）
              └──▶ 向量文本（语义精简）  ──▶ 候选人索引

岗位 JD   ──解析──▶ 关键词/向量文本（公司+职位+JD原文+结构化）
              └──▶ 硬条件（年限/学历/地点/技能） ──▶ 岗位索引

[用户输入]    ──▶ 关键词/向量/混合/筛选 ──▶ 候选人索引  （方式 1~4）
[候选人文本]  ──▶ 关键词/向量/混合 ──▶ 岗位索引        （方式 5~7）
[岗位画像]    ──▶ 关键词/向量/混合 ──▶ 候选人索引        （方式 8~10）
```

# 七、一句话记忆

- **关键词** = 比字面，认"写过什么字"。
- **向量** = 比语义，认"是什么意思"。
- **混合** = 字面 + 语义一起比，取长补短。
- **精确筛选** = 比确定字段，不猜。
- **人选匹配岗位** = 拿"人"去岗位库里搜。
- **岗位匹配人选** = 拿"岗位画像"去人才库里搜。
