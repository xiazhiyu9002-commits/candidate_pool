# 可持续 AI 供应商接入架构设计

## 1. 背景与目标

当前系统把供应商、Base URL、模型名和能力路由分散硬编码在设置模型、供应商工厂和前端表单中。文本、视觉、Embedding、Rerank 的选择规则不一致，保存配置后还需要重启。对没有技术背景的个人猎头而言，配置成本高；对不经常升级的软件而言，供应商改地址、换模型或调整参数也容易导致功能失效。

本次改造的目标是：使用者仍可自由选择 API，但日常配置只需要“选择供应商 → 粘贴 API Key → 自动检测 → 使用推荐方案”；应用通过稳定的内部能力协议、可更新的供应商目录和故障回退吸收大部分 API 与模型变化。

“一次适配”不承诺永久兼容所有未来破坏性协议。它具体表示：

- 模型上下架、推荐模型变化、Base URL 和兼容路径变化可通过签名目录更新，无需发布新程序。
- OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 三类生成协议，以及 OpenAI-compatible Embedding 和 Cohere-compatible Rerank，可通过目录组合，无需修改业务代码。
- 供应商推出全新鉴权或全新请求协议时，才需要升级程序；应用应继续使用最后可用配置或本地降级，不能整体崩溃。

## 2. 范围

首批内置供应商目录覆盖 DeepSeek、硅基流动、阿里云百炼/通义千问、智谱、Moonshot/Kimi、MiniMax、百度千帆、腾讯混元、火山方舟和自定义 OpenAI-compatible 服务。目录中的端点和推荐模型属于可更新数据，不属于业务代码。

能力分为：

- `text_generation`：简历解析、JD 解析、组织文本解析、搜索改写、画像生成、BD Agent 规划与总结。
- `vision_generation`：扫描版简历 OCR/视觉理解。
- `embedding`：向量检索。
- `rerank`：搜索结果重排。
- `web_search`：保留 Tavily/SerpApi 现有独立配置，本次只统一状态展示，不将其伪装成大模型能力。

不在范围内：账号体系、多人权限、计费代充、API Key 托管服务、自动购买额度、修改候选人/JD/招聘流程数据库结构、允许远程目录下发可执行代码或任意请求模板。

## 3. 使用者体验

设置页顶层改为“AI 服务”“邮箱与提醒”“数据与备份”三个区域。AI 服务默认只显示当前状态、推荐方案和“添加/更换 AI 服务”。高级路由、Base URL、自定义模型和故障切换顺序默认折叠。

添加连接使用四步向导：

1. 选择供应商；优先展示“推荐”“国内可用”“已有配置”。
2. 粘贴 API Key；Base URL 使用目录默认值，不要求普通使用者填写。
3. 自动读取模型列表并做最小调用探测；失败时返回可行动的中文原因，如 Key 无效、余额不足、模型无权限、地址不可达，而不是统一显示“调用失败”。
4. 展示系统建议的能力分配，使用者可一键启用，也可在高级设置中按能力换模型。

同一个人既是普通使用者也是管理员，因此不增加角色或权限切换。危险操作通过说明和二次确认控制：切换 Embedding 模型若向量维度或语义空间变化，必须明确提示并触发现有索引重建流程；不能静默切换。

## 4. 后端架构

### 4.1 稳定内部协议

所有招聘业务模块只依赖 `GenerationClient`、`EmbeddingProvider`、`RerankerProvider` 和 `OCRProvider` 等能力接口，不再识别 DeepSeek、硅基流动等供应商名称。

生成请求统一为 `GenerationRequest`：消息、期望输出类型、可选 Pydantic 结果模型和任务标签。响应统一为 `GenerationResult`：最终正文、供应商、模型、请求 ID、耗时和回退次数。供应商返回的 `reasoning_content` 不写日志、不返回前端、不作为最终正文；最终 `content` 为空视为响应结构错误。

结构化输出按能力协商：优先 JSON Schema，其次 JSON Object，最后使用严格 JSON 提示词并在本地校验。一次请求最多做一次格式降级，避免重复计费失控。只有模型档案声明支持时才发送 `temperature`、`reasoning_effort`、视觉输入等可选字段。

### 4.2 供应商目录

目录是只包含声明式数据的 JSON，字段包括目录版本、供应商标识、显示名、鉴权类型、协议族、默认 Base URL、模型列表接口、能力端点、推荐模型、模型能力提示和帮助链接。协议族必须来自代码内枚举；目录不能增加任意 HTTP 方法、任意 Header 模板或可执行表达式。

加载优先级为：已验证的远程缓存 > 应用内置目录。应用启动时若缓存超过 24 小时则后台刷新，设置页也提供手动刷新。远程文件使用 Ed25519 签名，应用内置公钥；只有签名正确、Schema 正确、版本不回退的目录才能原子替换缓存。下载、签名或解析失败时继续使用最后验证成功的目录，并展示“目录更新失败，正在使用上次版本”。

生产安装包必须包含发布方控制的 HTTPS 目录地址和 Ed25519 公钥。若构建时没有这两个值，构建可以用于开发，但不得标记为生产发布。首发内置目录使离线或目录服务器故障时仍可配置。

### 4.3 连接、模型发现与探测

`ProviderConnection` 保存连接 ID、供应商 ID、显示名、加密后的 API Key、可选 Base URL 覆盖、启用状态和最后探测摘要。API Key 继续使用现有 `EncryptionService`，GET 接口只返回 `has_secret` 与掩码，不返回密文或明文。

模型发现先调用目录声明的模型列表端点；端点不支持或被禁止时，回退到目录推荐模型。发现结果不是直接可信能力，必须通过小型探测确认：文本生成、结构化 JSON、视觉、Embedding、Rerank 分开探测。探测结果带 24 小时 TTL，并记录为配置文件缓存，不进入招聘业务数据库。

### 4.4 按能力路由和故障回退

`CapabilityRouter` 为每项能力维护有序路由：主连接/模型、备用连接/模型、本地降级。只有使用者已配置并启用的连接才可成为跨供应商回退目标，系统不能把数据悄悄发送给未经使用者授权的第三方。

以下错误允许尝试下一个远程目标：网络超时、HTTP 429、供应商 5xx、模型下架或无权限。401/403 的 Key 错误直接标记连接异常；请求内容违规、Pydantic 校验失败和业务输入错误不跨供应商重试。单次业务请求每项能力最多两个远程尝试，然后进入已有本地能力或返回明确错误。

运行时使用不可变 `ProviderSnapshot`。配置保存并探测成功后原子替换快照；正在执行的请求继续使用旧快照，随后安全关闭旧 HTTP 客户端，因此文本/视觉/Rerank 更新无需重启应用。

Embedding 是例外：任何模型或供应商变化都视为语义空间变化，即使向量维度相同也不能直接复用旧索引。保存配置后保持旧 Embedding 生效，直到使用者确认并完成索引重建；重建成功后再切换快照，失败则保留旧索引和旧模型。

## 5. API 设计

新增并稳定以下接口：

- `GET /api/ai/catalog`：返回目录版本、供应商摘要和是否陈旧。
- `POST /api/ai/catalog/refresh`：刷新签名目录，返回实际采用的版本及状态。
- `GET /api/ai/connections`：返回脱敏连接列表。
- `POST /api/ai/connections`：创建连接；API Key 只在该请求传入。
- `PUT /api/ai/connections/{connection_id}`：修改名称、Base URL 或更换 Key。
- `DELETE /api/ai/connections/{connection_id}`：仅在未被路由引用时删除，否则返回引用的能力列表。
- `POST /api/ai/connections/{connection_id}/discover`：发现模型。
- `POST /api/ai/connections/{connection_id}/probe`：按能力做真实最小调用。
- `GET /api/ai/routes`：返回当前和待激活路由。
- `PUT /api/ai/routes`：校验并保存路由；非 Embedding 路由立即热加载。
- `POST /api/ai/routes/embedding/activate`：确认索引重建并在成功后激活 Embedding 路由。

保留现有 `/api/settings` 的邮箱、提醒和搜索 API 配置。旧 AI 字段在一个兼容周期内仍可读取，但新前端不再写入；旧 `/api/settings/vendors` 返回弃用标记并映射到新目录，避免一次性破坏测试或旧安装包前端。

## 6. 配置与数据迁移

AI 配置使用 `data_root/config/ai-providers.json`，`schema_version` 固定为 `2`。签名目录缓存使用 `data_root/config/provider-catalog-cache.json`，探测缓存使用 `data_root/config/provider-probes.json`。所有写入采用“临时文件 + flush/fsync + replace”的原子方式，并保留单份 `.bak`。

首次启动若不存在 v2 文件，则从现有 `settings.json` 的 `deepseek_*`、`siliconflow_*`、`text_*`、`vision_*`、`embedding_*`、`rerank_*` 字段生成连接和路由。迁移规则必须幂等：存在 v2 文件后不再重新迁移；旧字段暂不删除，以便旧版本回退；重复的 Base URL + Key 只生成一个连接。密钥在解密旧值后立即用同一加密服务写入新文件，日志中不出现明文。

候选人、JD、组织、招聘流程、任务和向量元数据的 SQLite/LanceDB 数据结构不因配置迁移而改变。只有使用者主动切换 Embedding 路由时才运行现有索引重建。

## 7. 前端结构

`SettingsPage` 不继续堆叠供应商字段，而是组合三个独立组件：

- `AiServicesPanel`：状态总览、推荐方案、连接卡片、目录状态。
- `ConnectionWizard`：选择供应商、输入 Key、发现与探测、确认启用。
- `AdvancedRoutingPanel`：按能力选择主/备连接与模型，并处理 Embedding 重建确认。

前端类型从 `App.tsx` 拆到 `desktop/src/ai/types.ts`，API 调用集中在现有 `BackendClient`。错误展示使用后端稳定错误码映射成中文行动建议；密钥输入保存成功后立即清空，React state 中不长期保留。

## 8. 安全与隐私

- 所有 API Key 静态存储必须加密；响应、日志、错误、遥测和备份清单不得包含明文。
- 目录更新只接受 HTTPS 与正确 Ed25519 签名；禁止远程目录覆盖公钥、目录 URL 或添加非枚举协议。
- 自定义 Base URL 仅允许 `https://`；开发环境显式开启时才允许 loopback HTTP。
- 故障回退只能在使用者已保存并启用的连接之间进行。
- 探测使用固定的无个人信息测试文本，不能上传真实简历、JD 或候选人信息。
- 结构化日志只记录连接 ID、供应商 ID、模型、状态码、请求 ID、耗时和错误码。

## 9. 验收标准

1. 新使用者可在 3 分钟内仅凭供应商名称和 API Key 完成 AI 配置，不需要手填 URL 或模型名。
2. 文本、视觉、Embedding、Rerank 可选不同供应商；默认推荐方案只要求最少连接数。
3. 更新非 Embedding 路由后无需重启，下一次请求使用新快照。
4. Reasoning 模型不因固定 `temperature=0`、不支持 `response_format` 或返回 `reasoning_content` 而失败或泄露思考内容。
5. 模型下架或限流时，系统只在已授权连接中回退，并在结果诊断中说明发生了回退。
6. 远程目录签名错误、结构错误、降版本或网络失败时继续使用最后验证版本。
7. 旧 `settings.json` 可幂等迁移到 v2，密钥不泄漏；招聘业务数据库无 Schema 迁移。
8. 切换 Embedding 前必须重建索引，重建失败时旧模型与旧索引仍可用。
9. PyInstaller sidecar 包含内置目录和公钥，断网冷启动仍能列出供应商并使用已有配置。
10. 后端单元/API/运行时测试、前端组件测试和安装包冒烟测试全部通过。
